
Axios обрано для централізації конфігурації HTTP-клієнта, знучної типізації та маштабованості.

## Структура папок

api

Містить усю логіку взаємодії з сервером. Тут знаходиться HTTP-клієнт (Axios) та функції для роботи з API (отримання, створення, редагування та видалення постів і коментарів). Цей шар не містить бізнес-логіки чи UI.

hooks

Містить кастомні React Hooks, побудовані на TanStack Query. Вони відповідають за отримання даних, кешування, мутації, optimistic updates та взаємодію між UI і шаром API.

components

Повторно використовувані UI-компоненти (PostCard, SearchBar, Loader, EmptyState тощо). Компоненти не працюють із сервером напряму та отримують усі дані через props.

screens

Екрани застосунку (Feed, Post Details, Edit/Create Post). Відповідають за побудову інтерфейсу та композицію компонентів, використовуючи кастомні hooks для отримання даних.

navigation

Конфігурація React Navigation: стек навігації, типи маршрутів та налаштування переходів між екранами.

storage

Робота з локальним сховищем (AsyncStorage). Використовується для збереження локальних змін (створені, відредаговані та видалені пости), а також UI-налаштувань (останній пошуковий запит тощо).

styles

Глобальні стилі застосунку: кольори, типографіка, відступи та спільні стилі, що використовуються в різних компонентах.

query

Конфігурація TanStack Query. Тут знаходяться QueryClient та централізовані queryKeys, які використовуються для керування кешем.

types

Спільні TypeScript-типи та інтерфейси (Post, Comment, User тощо), що використовуються в усьому застосунку.

utils

Допоміжні функції, які не залежать від React або UI (наприклад, форматування тексту, debounce, утиліти для роботи з даними).

constants

Константи застосунку: маршрути, базові URL, значення за замовчуванням, ключі сховища та інші незмінні дані.
